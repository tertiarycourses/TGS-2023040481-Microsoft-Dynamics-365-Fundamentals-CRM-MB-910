# Lab 5 - Case Lifecycle, Queues, Routing, SLAs, and Entitlements

## Objective

Describe Dynamics 365 Customer Service case management, queues, routing, SLAs, and entitlements.

## Scenario

Contoso receives support requests through email, phone, and web forms. Cases are assigned manually, urgent issues are sometimes missed, and customers want clearer service expectations.

## Prerequisites

- Review Dynamics 365 Customer Service case concepts.
- Review queues, routing, SLAs, and entitlements.

## Tasks

### Step 1 - Define case types

Create a case type table:

| Case type | Example | Priority | Target response |
|-----------|---------|----------|-----------------|

Include:

- Billing question
- Maintenance request
- Complaint
- Emergency fault
- Warranty enquiry

### Step 2 - Map the case lifecycle

Describe:

1. Case is created.
2. Case is categorized.
3. Case is routed to queue.
4. Agent investigates.
5. Knowledge article is suggested.
6. Customer receives response.
7. Case is resolved.
8. Customer satisfaction is measured.

### Step 3 - Design queues and routing

Create a routing table:

| Queue | Case criteria | Assigned team |
|-------|---------------|---------------|

Add at least four queues, such as:

- Billing
- Technical support
- Field dispatch
- Complaints

### Step 4 - Define SLA rules

Create SLA rules:

| Priority | First response target | Resolution target | Escalation |
|----------|-----------------------|-------------------|------------|

### Step 5 - Define entitlements

Create entitlement examples:

| Customer plan | Included support | Case limit | SLA |
|---------------|------------------|------------|-----|

Include basic, premium, and enterprise service plans.

## Deliverable

Submit:

- Case type table
- Case lifecycle map
- Queue and routing table
- SLA rules
- Entitlement examples

## Checkpoint questions

1. What is the difference between a case and an activity?
2. Why are queues useful for service teams?
3. How do SLAs and entitlements support customer expectations?
